# Limitations

- This is a research simulation, not a production banking system. It uses a single Node process and SQLite, with a local Redis-compatible service for nonce and session records.
- Memurai Developer 4.2.3, not stock Redis, was used for the Phase 0 baseline. Memurai listens on IPv4 only in this environment; use `REDIS_URL=redis://127.0.0.1:6379` rather than `localhost` if IPv6 resolution selects `::1`.
- No TLS is configured by default. The login response carries the per-session signing key, so a passive observer of the default HTTP login can learn that key. The stated network-attacker-without-the-key model assumes protected key delivery; this default local setup does not meet that assumption and cannot support a production network-security claim. Transport confidentiality and server identity are not provided here.
- `PROXY_REDACT_LOGIN=true` redacts login request and response bodies from the proxy's attacker-visible capture file but forwards them unchanged to the client. This is capture hygiene for controlled experiments, not transport protection; a real on-path observer of the default HTTP exchange can still read the session key. E1 S9 treats a leaked key as a separate attacker capability.
- Baseline requests were generated by a script that held the signing secret. That does not model the attacker. The modeled network attacker has no signing secret.
- Anyone holding the browser's client-side session key can forge requests until the server-side session expires. The key lives in client memory; this design does not defend against client compromise.
- All latency is localhost latency and is not representative of a real network. Delay and clock-skew distributions used in future experiments are assumptions unless a cited external measurement is added.
- The dashboard scans nonce keys for visualization when enabled. That scan is a demo implementation artifact, not a property of the replay defenses. Benchmark requests must run with `VIZ_ENABLED=false`; any visualization-on curve must be labeled separately.
- The session login demo defaults to a locally configured PIN. Configure `DEMO_PIN` before any environment outside the isolated simulation.

## To do before making the repository public

The repository history contains previously used signing material. The current key rotation does not remove older blobs. Do not treat `.gitignore` or a cleaned working tree as history cleanup. The following procedure is a future, coordinated operation; it has **not** been run in this workspace:

1. Stop pushes and ask every collaborator to stop pushing. Rotate/revoke all exposed keys and credentials first.
2. Make and verify a full offline backup. Create a fresh disposable clone of the repository and perform the rewrite there, not in the working copy.
3. Install `git-filter-repo`. Create an untracked, access-restricted `replacements.txt` outside the repository. Put one line per old value in the form `literal:<old-value>==>***REMOVED***`; never paste the values into a command transcript, issue, or committed file.
4. In the disposable clone, remove only the historical secret-bearing paths that must not exist (for example committed `.env` files; retain safe templates only if they contain no secret), and replace the old values in all remaining files:

   ```powershell
   git filter-repo --force --replace-text C:\secure\path\replacements.txt --path server/.env --path client/bank/.env --invert-paths
   ```

   If other secret-bearing paths are found, list each explicitly in the same `--path` filter or run a separately reviewed path-filter operation. The `--invert-paths` option removes the listed paths; it must not be omitted for that command.
5. Search every reachable ref and every tracked blob for the old values without printing them. Inspect the rewritten commit graph and run the project checks. Keep the replacement file outside the repository and securely remove it only under the organization's secret-handling policy.
6. Coordinate with the hosting provider and all collaborators before any force update. `git-filter-repo` may remove the `origin` remote as a safety measure; restore the intended remote only after review. A future authorized publication may require force-updating all affected branches and tags, then having collaborators reclone. Do not run a force push until explicitly approved.

History rewriting can invalidate commit signatures, pull requests, forks, tags, and collaborators' clones. This document records a safe plan only; no rewrite or remote operation was performed here.
